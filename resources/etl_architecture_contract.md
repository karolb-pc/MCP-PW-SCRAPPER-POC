# ETL Architecture Contract (agent-facing)

> This file is the single source of truth for the structure of every scraper generated by
> `generate-self-healing`. The host injects it verbatim into the generation prompt before every
> run. Editing this file changes what all future generated scrapers look like — no code change
> required. It is committed to the repo on purpose.
>
> Placeholders the host substitutes at runtime: `<SLUG>`, `<MODULE_PATH>`, `<SOURCE_URL>`,
> `<OUTPUT_PATH>`, `<TARGET_DIR>`.

You must produce a **full ETL project**, not a one-off script. This is the same layered ETL shape
used by every ETL in this organization: layer separation (extractor / transformer / validator /
loader), config-driven wiring via a `CONFIG` dict consumed by a `BaseETL` subclass, Pydantic data
contracts, and a Click `main.py` entrypoint. The only sink is a local JSON file (there is no
database, so no ORM layer).

## Required directory layout

```
<TARGET_DIR>/
  __init__.py
  scraper_target.json          # manifest (you write this — see below)
  settings.py                  # SOURCE_URL, SOURCE_NAME, default output/diagnostics/export paths
  etl.py                       # CONFIG dict + <Name>ETL(BaseETL) with async run()
  extractor/__init__.py
  extractor/<SLUG>.py          # <Name>Extractor(AbstractExtractor).extract(...)
  transformer/__init__.py
  transformer/<SLUG>.py        # <Name>Transformer(AbstractTransformer).transform(...)
  validator/__init__.py
  validator/<SLUG>.py          # <Name>Validator.validate(payload) — guards output
  schema/__init__.py
  schema/<SLUG>.py             # Pydantic item/payload models (the data contract)
  main.py                      # Click `cli` with `run` and `validate` commands
```

## Shared base classes — import, never redefine

- `from src.contracts.extractor import AbstractExtractor` → implement `async def extract(self, *args, **kwargs)`.
- `from src.contracts.transformer import AbstractTransformer` → implement `def transform(self, *args, **kwargs)`.
- `from src.contracts.base import BaseETL` → subclass for the ETL orchestrator (its `__init__` builds
  `extractor` / `transformer` / `validator` / `loader` from the `CONFIG` dict).
- `from src.contracts.local_json import LocalJsonLoader` → use as the loader. Do NOT write your own
  loader; the sink is a local JSON file.

## Output payload shape (the loader writes exactly this)

```json
  "source_url": "<SOURCE_URL>",
  "user_prompt": "...",
  "items": [ { "...": "..." } ],
  "summary": { "items": 0 },
  "meta": { "mode": "generate_self_healing", "scraper": "<SLUG>" }

```

## main.py entrypoint

A Click group `cli` exposing:
- `run` with options `--output`, `--diagnostics-dir`, `--export-dir`, `--browser`, `--quiet`; it
  builds `<Name>ETL(config=CONFIG)` and runs it.
- `validate <path>` that loads the JSON and runs `<Name>Validator`.

It MUST be runnable as: `uv run python -m <MODULE_PATH>.main run`.

## scraper_target.json — you must write this manifest

```json
{
  "name": "<SLUG>",
  "kind": "folder_etl",
  "source_url": "<SOURCE_URL>",
  "files": ["main.py", "etl.py", "settings.py", "extractor/<SLUG>.py", "transformer/<SLUG>.py", "validator/<SLUG>.py", "schema/<SLUG>.py"],
  "allowed_paths": ["etl.py", "settings.py", "extractor/<SLUG>.py", "transformer/<SLUG>.py", "validator/<SLUG>.py", "schema/<SLUG>.py"],
  "run_command": ["uv", "run", "python", "-m", "<MODULE_PATH>.main", "run", "--quiet", "--browser", "playwright"],
  "verification_command": ["uv", "run", "python", "-m", "<MODULE_PATH>.main", "run", "--quiet", "--browser", "playwright"],
  "output_path": "<OUTPUT_PATH>"
}
```

`allowed_paths` are the only files the self-healing repair agent may later patch, so list every
file that carries scraping logic and none of the infrastructure files.

## Layer rules (must hold in the generated code)

- The CLI holds no scraping logic; extraction lives in the extractor, shaping/normalization in the
  transformer, output guards in the validator, and file writing in the loader.
- The loader is source-agnostic — it only writes the payload it is given.
- The validator must FAIL on empty/degenerate payloads instead of writing an empty output file.
- Deterministic for this one scrape goal: no free browsing, no CAPTCHA/anti-bot bypass.
- No secrets in code or output; credentials only via env, never printed or persisted.

## Definition of done

- The project matches the layout above and imports the shared contracts.
- `uv run python -m compileall <TARGET_DIR>` succeeds.
- A first `run` writes `<OUTPUT_PATH>` with real scraped data matching the payload shape, or a clear
  structured blocker report if the source is blocked.
